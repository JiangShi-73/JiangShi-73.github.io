去年我在团队里推一套新组件库，推了三个月，采用率 20%。

复盘的时候发现，问题不在组件质量——问题在于，大家不知道什么时候该用哪个组件。文档里写的是「Button 支持 size、variant、loading」，但没写「这个场景应该用主按钮还是次按钮」。

## 组件库给的是零件

组件库回答「有什么」，设计系统回答「怎么选」：

- 什么情况下用主按钮，什么情况下用文字按钮
- 表单错误应该出现在字段下方还是顶部
- 空状态该不该放插画
- 数字用不用千分位

这些决定写不进 TypeScript 类型里，但决定了界面是否一致。

## 我们后来怎么做的

做了三件很土的事：

1. 写「决策树」而不是 API 文档：三句话内告诉你选哪个
2. 所有组件文档第一屏放真实截图，不是代码
3. 建一个「反例」页面，展示错误用法

采用率在两个月内到了 85%。不是组件变好了，而是选择变便宜了。

## 一句话

组件库降低的是书写成本，设计系统降低的是判断成本。新人第一天能不能改对界面，取决于后者。
